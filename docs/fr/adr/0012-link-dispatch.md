# ADR 0012 — Ouvrir les liens de chemins de dx : un plugin qui aiguille, et protège

- **Statut** : accepté
- **Date** : 2026-11-22

## Contexte

Le plugin Claude Code dx ([ADR 0009 de CC-Plugins](https://github.com/IMSike/CC-Plugins/blob/main/docs/fr/adr/0009-clickable-paths.md)) dessine les chemins des réponses de Claude en hyperliens de terminal `dx-open:///C:/…/fichier#L12-L14`, dans Herdr seulement, et seulement les chemins qui existent. dx, un plugin Claude Code à function hooks, ne peut ouvrir un fichier dans un autre programme sans en lancer un lui-même, et c'est Herdr qui reçoit le clic.

Herdr envoie un ctrl+clic sur une URL à l'action d'un plugin quand l'un des motifs `[[link_handlers]]` du plugin la reconnaît, tant que la capture de la souris est active ; sinon il n'ouvre que les liens http(s). L'action est lancée sans shell, depuis le dossier du plugin, avec `HERDR_PLUGIN_CLICKED_URL` et `HERDR_PANE_ID`. Un essai réel (Herdr 0.9.5, Windows) a lancé une telle action en 0,2 s environ, sans fenêtre de console. herdr-explorer (`gcaudan.explorer`) montre un fichier dans son aperçu, `herdr-explorer peek <fichier>[:<lignes>]`, lancé depuis un pane Herdr ; il refuse les dossiers, et prend pour siens `HERDR_PLUGIN_ID`, `HERDR_PLUGIN_STATE_DIR` et `HERDR_PLUGIN_CONTEXT_JSON` quand ils sont définis.

Le mainteneur veut qu'un clic ouvre ce que l'utilisateur a choisi : l'aperçu de herdr-explorer, le fichier sélectionné dans l'Explorateur de fichiers, ou le programme que Windows lui associe ; un dossier toujours dans l'Explorateur de fichiers ; et un fichier qui peut lancer du code à l'ouverture (un programme, un script, un installeur, un raccourci, un document à macros…) jamais ouvert ainsi, sauf si un réglage, désactivé par défaut, le permet. L'URL du lien peut venir de n'importe où : le modèle peut écrire un lien Markdown avec n'importe quel texte et n'importe quelle cible, et n'importe quel programme de n'importe quel pane peut écrire un lien OSC 8.

Options étudiées :

| Option | Pour | Contre |
|---|---|---|
| Ce que fait Herdr lui-même | Rien à écrire | Herdr n'ouvre que http(s) ; rien pour un schéma à soi |
| L'action dans le plugin menu | Rien de plus à installer | La fonction de dx liée au menu ; le binaire du menu grossit d'une tâche sans rapport |
| **Un plugin à part, `links`** | Installé avec dx seul ; petit ; l'ouverture et la protection en un seul endroit testé | Un plugin de plus |
| L'action en PowerShell | Pas de compilation | Hors du Rust du dépôt ([ADR 0001](0001-rust-cargo-workspace.md)) ; `powershell` pris dans le `PATH` ; plus lent ; non testé |
| Ce qu'il faut faire écrit dans l'URL (`dx-open:default/…`) | Le clic porte le choix | Qui écrit un lien choisit ; la protection demanderait encore un réglage |
| **L'URL ne porte que le chemin ; le choix et la protection sont des réglages du plugin** | Un lien forgé fait au plus ce que fait un vrai | Le choix se règle dans Herdr, pas dans Claude Code |
| Une liste des types qui s'exécutent (liste noire) | Ouvre tout le reste | Un type oublié, ou un programme installé plus tard qui exécute ses fichiers, ouvre du code |
| **Une liste des types qui peuvent s'ouvrir (liste blanche), modifiable par l'utilisateur** | Un type auquel personne n'a pensé est sélectionné, pas ouvert | Un type sans danger absent de la liste est sélectionné tant que l'utilisateur ne l'ajoute pas |

## Décision

Un nouveau plugin, `links` (`imsike.links`, binaire `herdr-links`, Windows seulement), déclare une action `open` et un gestionnaire de liens `pattern = "^dx-open:"`. `herdr-links open` :

1. **Lit l'URL, et rien d'autre qu'elle** : `dx-open:///X:/…`, 2048 octets au plus, sans hôte ni requête, ses segments décodés (pourcentages) en UTF-8 strict, un fragment facultatif `#L12` ou `#L12-L14`. Refusés : un caractère de contrôle, un séparateur ou deux-points dans un segment (un flux de données alternatif), un segment `.`, `..` ou vide, un nom qui finit par un point ou une espace, un caractère que Windows refuse dans un nom ou lit comme un joker (`* ? < > |`), une virgule, un point-virgule ou un guillemet droit (l'Explorateur de fichiers coupe sa ligne de commande aux virgules), un signe pour cent (pour qu'aucun `%NOM%` ne puisse jamais être lu comme une variable en chemin vers l'Explorateur de fichiers), un nom de périphérique Windows (`CON`, `PRN`, `AUX`, `NUL`, `COM0`–`COM9`, `LPT0`–`LPT9`, `COM¹`–`COM³`, `LPT¹`–`LPT³`, `CONIN$`, `CONOUT$`, en majuscules ou minuscules, avec ou sans extension), un CLSID comme dernière extension (`x.{8-4-4-4-12}`, que l'Explorateur de fichiers ouvre comme l'objet qu'il désigne), un caractère invisible : tout caractère de la catégorie générale Unicode Cf (format), Zl ou Zp (séparateurs de ligne et de paragraphe), ou de la propriété Default_Ignorable_Code_Point, tels qu'Unicode 16.0 les liste (caractères de largeur nulle, de remplissage, sélecteurs de variante, étiquettes, contrôles bidirectionnels, caractères d'annotation interlinéaire U+FFF9–U+FFFB, contrôles de format d'autres écritures…), qui feraient passer un nom pour un autre ; un caractère à usage privé (la catégorie générale Co), qu'une police peut dessiner n'importe comment ; la configuration braille vide U+2800, qui s'affiche comme un blanc ; un non-caractère Unicode (U+FDD0–U+FDEF, et les deux derniers points de code de chaque plan, U+FFFE, U+FFFF, U+1FFFE… U+10FFFF).
2. **Vérifie la vraie cible** : le chemin rendu canonique (liens symboliques et jonctions suivis, noms courts DOS rendus longs, un lecteur `subst` remplacé par son dossier), refusé si cela échoue, aboutit sur un partage réseau ou hors d'un lecteur local (un chemin d'espace de noms de volume ou de périphérique), compte 260 unités UTF-16 ou plus (la limite `MAX_PATH` de Windows), ou si ses vrais noms enfreignent les règles de l'étape 1. Le type est lu sur le vrai nom, et chaque commande est construite à partir de ce chemin canonique.
3. **Lit ses réglages** dans `links.toml`, dans son dossier de configuration ([ADR 0004](0004-plugin-settings.md)), à chaque clic :
   - `file` : `"preview"` (par défaut), `"select"` ou `"application"` ;
   - `open_types` : les types que l'application par défaut peut ouvrir, sans le point, casse indifférente ; par défaut des types qui ne lancent pas de code par eux-mêmes (leur visionneuse peut toujours avoir des failles), sauf le JavaScript d'un PDF, que son lecteur (Acrobat, celui d'Edge) peut exécuter, dans son bac à sable : texte et documents, données et configuration, code source que Windows n'exécute pas, images, son et vidéo (ni `.js`, `.py`, `.ps1`, `.sh`, ni `.html`, `.svg`, `.xml`, qu'un navigateur ouvre avec leurs scripts, ni les fichiers OpenDocument et leurs macros, ni `.rtf`) ;
   - une section **Danger** : `run_programs` (`false` par défaut), qui laisse un fichier d'un autre type s'ouvrir avec son programme ; `confirm_programs` (`true` par défaut), qui demande alors d'abord.

   Toute extension peut être un type, avec ou sans son point, casse indifférente (`$$$`, `!ut`, `(x)`…) ; seule la dernière compte : `gz`, pas `tar.gz`. Un type qui contient un caractère qu'aucun nom de lien ne peut porter (`\ / : * ? " < > | , ; %`, un caractère de contrôle, un caractère invisible, à usage privé ou braille vide, un non-caractère Unicode, comme à l'étape 1), ou qui finit par un point (`md.`), est un type faux. Un fichier ou un réglage absent garde sa valeur par défaut ; un type faux est laissé de côté, journalisé, les autres gardés. Un fichier inutilisable (une erreur de syntaxe, un réglage inconnu) est mis de côté, ce que dit une notification à chaque clic, et les fichiers ne sont alors que sélectionnés : un fichier abîmé n'ouvre jamais plus que ce qu'a choisi l'utilisateur. Un fichier introuvable, Herdr ne donnant pas de dossier de configuration, est traité de même.
4. **Ouvre**, l'Explorateur de fichiers toujours en `%SystemRoot%\explorer.exe` (`%windir%` à défaut), par son chemin complet, depuis ce dossier, sans les variables `HERDR_*` de Herdr (ce qu'il ouvre tourne hors de Herdr ; quand une fenêtre de l'Explorateur est déjà ouverte, `explorer.exe` passe la demande à cet Explorateur déjà lancé, qui démarre le programme avec son propre environnement : les variables ne sont retirées que de ce que lance lui-même l'`explorer.exe` que démarre le plugin), sa ligne de commande écrite comme il la lit :
   - un dossier : `/select,"<dossier>"`, le dossier sélectionné dans son parent ; jamais `explorer.exe <dossier>`, qui lancerait un fichier mis à sa place ;
   - un fichier avec `preview` : herdr-explorer, trouvé par `plugin.list` de Herdr (`bin\herdr-explorer.exe` sous sa racine, activé), lancé en `peek <fichier>[:<lignes>]` depuis son dossier, sans les variables `HERDR_PLUGIN_*`, avec `HERDR_PANE_ID`, sans fenêtre de console, 3 s au plus : au-delà, herdr-explorer est arrêté et rien d'autre ne s'ouvre, car ce qu'il a lancé peut encore montrer le fichier (un `herdr` qu'il exécute lui survit), et une notification « Aperçu lent » le dit. Sans herdr-explorer, ou quand l'aperçu échoue, comme `application` ;
   - un fichier avec `select` : `/select,"<fichier>"`, jamais ouvert avec son programme ;
   - un fichier avec `application` : `explorer.exe "<fichier>"`, le programme que Windows lui associe, quand son type est dans `open_types`. Un autre est sélectionné à la place, avec une notification Herdr qui dit pourquoi, sauf si `run_programs` est activé ; alors, avec `confirm_programs`, un popup du plugin montre le chemin canonique et le type du fichier, pour un raccourci (`.lnk`, `.url`, `.pif`, `.website`, `.application`, `.appref-ms`, `.rdp`, `.scf`, `.settingcontent-ms`, `.shb`, `.xnk`, `.library-ms`, `.searchConnector-ms`, `.search-ms`, `.wsh`, `.jnlp`, `.ica`) une ligne rouge qui dit que sa cible n'est pas affichée, et ne l'ouvre que sur Entrée, après avoir vérifié de nouveau le chemin et `run_programs` (seule une Entrée tapée seule, sans Ctrl, Alt ni Maj, après 1,1 s confirme : toute autre touche, Échap ou Entrée modifiée compris, annule aussitôt, même pendant les 1,1 premières secondes ; une Entrée entendue seulement après 1,1 s sans aucune Entrée, plus que le plus long délai de répétition de Windows, 1 s, chacune reçue dans ce délai le relançant ; l'Entrée prise quand elle est relâchée, appuyée une seule fois et sans répétition ; une Entrée suivie aussitôt d'autre saisie prise pour un collage, pas de confirmation tant que tout le chemin, et la ligne d'un raccourci, ne tiennent pas) ; sans, il s'ouvre aussitôt.

Un lien refusé, un chemin introuvable ou non local, ou un Explorateur de fichiers ou un popup qui ne peut pas s'ouvrir, donne une notification Herdr (`notification.show`, sans son), jamais une fenêtre modale ; chaque échec est aussi journalisé (`herdr plugin log list --plugin imsike.links`).

## Conséquences

- Aucune URL, quoi qu'il l'ait écrite, ne peut faire ouvrir au plugin un fichier d'un type hors de `open_types` avec son programme tant que `run_programs` est désactivé ; une fois activé, chaque ouverture de ce genre est montrée avec son vrai chemin et confirmée, sauf si `confirm_programs` est désactivé aussi.
- Un type absent de `open_types` est sans danger par défaut : sélectionné dans l'Explorateur de fichiers. Qui ajoute un type qui exécute du code (`exe`, `js`…) choisit de l'exécuter.
- Ce que fait un clic se choisit dans Herdr (`links.toml`), le même pour chaque lien ; dx n'a aucun réglage de ce genre et vérifie seulement qu'un chemin existe.
- Le fichier vérifié peut être remplacé avant d'être ouvert (une course TOCTOU) : le programme reste choisi d'après l'extension du nom vérifié, et remplacer le fichier demande déjà un accès en écriture à son dossier. La cible d'un raccourci peut changer de même, entre la confirmation et l'ouverture.
- Un lien peut faire afficher à l'Explorateur de fichiers un dossier choisi par le modèle : un `desktop.ini`, un `.lnk`, un `.url`, un `.scf` ou un `.library-ms` qui s'y trouve et dont l'icône pointe vers `\\hôte\…` (le `IconFile=\\hôte\…` d'un `.url`) peut faire se connecter Windows à cet hôte en SMB et lui envoyer le hachage NTLM de l'utilisateur ; toute fenêtre de l'Explorateur sur ce dossier en fait autant, mais c'est le plugin qui l'ouvre.
- Un fichier sélectionné n'est pas ouvert avec son programme, mais l'Explorateur le lit : avec son volet de visualisation activé, le sélectionner lance le gestionnaire d'aperçu de son type, et des gestionnaires de miniatures lisent les fichiers du dossier ; une faille de l'un d'eux rencontre un fichier choisi par le modèle, comme dans toute fenêtre de l'Explorateur sur ce dossier.
- Le chemin est rendu canonique, ses liens symboliques suivis, avant qu'un chemin réseau soit refusé : un lien symbolique vers `\\hôte\…` fait se connecter Windows à cet hôte en SMB, et peut lui envoyer le hachage NTLM de l'utilisateur, avant le refus.
- Les `open_types` par défaut gardent `docx`, `xlsx` et `pptx`, qui ne contiennent pas de macro à eux ; un `.docx` peut tout de même nommer un modèle sur un partage réseau (`attachedTemplate`, `\\hôte\…`) que Word va chercher sans demander, ce qui peut envoyer à cet hôte le hachage NTLM de l'utilisateur, les macros du modèle restant derrière l'avertissement d'Office.
- Les `open_types` par défaut gardent `pdf` : un PDF peut contenir du JavaScript, que son lecteur (Acrobat, celui d'Edge) peut exécuter en ouvrant le fichier (une `OpenAction`), dans son bac à sable.
- Les `open_types` par défaut gardent `csv` et `tsv` : Excel, quand il en ouvre un, évalue les formules que le fichier contient (une cellule qui commence par `=`).
- Le chemin d'un raccourci n'est pas ce qu'il lance : le popup dit de tout raccourci que sa cible n'est pas affichée, et n'en lit aucun. La cible d'un `.lnk`, dans des champs binaires, n'est pas décodée ; l'adresse d'un raccourci Internet n'est pas montrée non plus : le lecteur de `.url` de Windows n'est pas documenté et, dans un fichier UTF-16, passe sur certains caractères des noms de clés et de sections (U+00AD, U+FEFF, U+200D…), si bien qu'une adresse montrée par le popup pourrait différer de celle que Windows ouvre.
- herdr-explorer reste facultatif : sans lui, un fichier s'ouvre avec son programme, dans la limite de `open_types`.
- La capture de la souris de Herdr doit être active pour qu'un clic atteigne le plugin ; `experimental.detectURLs` désactivé dans Windows Terminal l'empêche de confier d'abord à Windows le texte `file://` cliqué avec ctrl. Les deux sont documentés.
- Windows seulement : le crate compile sous Linux, où les deux commandes ne font que journaliser.
- À réévaluer si Herdr change ses gestionnaires de liens, ou si dx cesse d'utiliser `dx-open:`.
